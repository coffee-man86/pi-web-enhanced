# pi-web 部署层 v1.0.0 发行说明（2FA 代理 / WSL 保活 / WSL 加固）

> 适用场景：有公网端口，希望工作电脑与手机都能访问同一套 pi + web UI（对话进度同步、一套环境多处使用），且要保障公网访问安全。

---

## 整体架构

```
公网 → [HTTPS 反代] → 2FA 代理(:42204) → pi-web(:25133)   ← 双因子认证入口
                        └→ 可选 /fb 文件管理器
WSL2 内：workspace 只映射宿主机工作区文件夹（AI 只能访问它）
        + 保活脚本防 VM 空闲回收 + 域名白名单
```

## 组件一：2fa-proxy（双因子登录代理）

### 🚨 登录无需用户名
登录页只有「密码 + 动态码」，代理自动注入 pi-web 的 Basic Auth 凭据——用户完全感知不到用户名。

### 首次登录引导（全新安装自动启用）
1. **首次登录**：默认用户名 `pi`，密码 `password`（首次登录专用，之后可改）
2. **强制绑定**：登录后页面直接显示 2FA 验证说明 + **本机专属二维码**（每次安装随机生成，不共享），手机身份验证器扫码绑定
3. 点「**我已经绑定**」→ 解除首次登录 → 之后按**正常 2FA 流程**（密码 + 动态码）验证
4. **密码模型统一**：绑定前后同一个密码（默认 `password`，可修改）

### 账户功能（左下角「帐号」）
- pi-web 侧边栏注入「**帐号**」按钮（在「系统」项后）
- 点开可**退出登录**（清除 24h cookie）和**修改密码**
- 修改密码安全校验：未绑定阶段无需动态码；绑定后需「当前密码 + 动态码」

### 安全特性
- **登录限速**：同 IP 60 秒内 5 次失败 → 锁定 60 秒
- **登录审计日志**：`[2fa] OK/FAIL ip=...`（journald）
- **24h 签名 cookie**：HttpOnly + SameSite=Lax，可退出清除
- **透明转发**：向 pi-web 注入 Basic Auth，用户免二次登录
- **可信代理密钥头**：`X-Piweb-Proxy-Token`，配合 pi-web 的 `PI_WEB_TRUST_PROXY_TOKEN` 防 IP 伪造
- **上游兼容修复**：转发时重写 `Origin`（防 403 Untrusted API）、剥离 `accept-encoding`（防 gzip 字节损坏导致页面刷不出来）、上游 401 时给出配置指引页

### 安装（3 步）
```bash
sudo bash setup.sh 42204 25133    # 代理端口 上游端口（交互式收集凭据）
# 1) 浏览器打开代理地址 → 首次登录（pi / password）
# 2) 扫码绑定身份验证器 → 点「我已经绑定」
# 3) 之后登录：密码 + 动态码
```

### ⚠️ 安全要求
- **必须前置 HTTPS**（Caddy/nginx + 证书），否则密码与 cookie 明文传输
- 首次登录的 `password` 默认口令仅用于绑定引导，绑定后请尽快在账户页修改

## 组件二：keepalive（WSL VM 保活）

- 解决 WSL2 空闲约 60 秒回收 VM 的问题（`vmIdleTimeout`），即使 systemd 常驻也会被关停
- 保持一个 `wsl.exe` 会话常驻 + 自动重连拉起
- 一个发行版的保活即可维持整个共享 VM；开机自启模板附后

## 组件三：wsl-hardening（WSL 文件系统加固）

- **只暴露工作区**：关闭整盘自动挂载（`/mnt/c` `/mnt/d` 等全部消失），仅 fstab 显式挂载工作目录
- **关闭 interop**：Linux 内无法再执行 `cmd.exe`/`powershell` 读宿主机 C 盘
- 确保 AI 只能访问你映射的工作区文件夹，符合「文件边界」诉求
- 每发行版独立配置；属于进程边界加固，不能替代虚拟机/容器隔离
